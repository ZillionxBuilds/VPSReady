## 1. Mission and final internal outcome

Build a portable native-style C#/.NET + Avalonia desktop application that safely performs the approved Core Basic workflows against Ubuntu over SSH.

The autonomous team has no real VPS. It must complete implementation and blind evidence, then Principal creates `release/0.1.0`. That branch is the first Owner real-VPS validation candidate.

At `READY_FOR_OWNER_VPS_TEST`, the Owner receives:

1. exact release branch and SHA;
2. versioned self-contained artifacts and SHA-256 checksums;
3. supported build/package/startup evidence matrix;
4. explicit `REAL VPS: NOT TESTED` risk statement;
5. staged Owner VPS test protocol and recovery prerequisites;
6. local structured operation journal and Activity UI;
7. Copy Safe Issue Report;
8. Export Sanitized Support Bundle;
9. known limitations/open non-blocking issues;
10. feedback prompt/runbook for release defects.

A release candidate is not stable and is not a claim of real VPS success.

## 5. Scope

Included:

- .NET 10 LTS C# solution;
- Avalonia desktop;
- self-contained Windows/macOS/Linux artifacts;
- Ubuntu remote target only;
- password initial SSH and explicit host trust;
- server overview;
- UFW basic management;
- local ED25519 generation;
- public-key deployment and separate key login verification;
- local OpenSSH config alias;
- approved package/reboot/hostname/timezone actions;
- structured Activity/operation journals, redaction, support export;
- stateful blind scenario harness;
- CI, automated tests, simulated Manual QA and Owner test package.

Excluded:

- Docker/Coolify/Fail2ban/Kubernetes;
- web/database/DNS/TLS/cloud-provider provisioning;
- monitoring/telemetry/accounts/analytics/advertising;
- hosted backend or remote agent;
- non-Ubuntu support;
- arbitrary shell;
- automatic password/root SSH disablement;
- stable signing/notarization without Owner decision/credentials.

## 6. Release-blocking invariants

- no silent host-key trust;
- changed host key fails closed;
- no credential/private-key leakage;
- no firewall enable before active SSH allow verification;
- no normal active SSH rule removal;
- no success before state verification;
- no destructive overwrite of SSH config/authorized keys;
- no unconditional fake success;
- no simulated evidence described as E5;
- no destructive action without explicit user intent;
- no automatic diagnostic upload;
- every failure has operation ID/error code/next action;
- support bundle is sanitized and reviewable.

```text

  VpsReady.Infrastructure/

tests/
  VpsReady.UnitTests/
  VpsReady.IntegrationTests/
  VpsReady.DesktopTests/
```

Names may simplify, but preserve:

- UI/application/core/infrastructure testability;
- one composition root;
- no SSH library or raw command in views;
- stable command/event/error catalogs;
- centralized redaction;
- stateful scenario host behind production-facing abstractions;
- production/test composition separation;
- no fake-success mode in shipped artifacts.

## 14. Risks and mitigations

### Simulation drift from real Ubuntu

Mitigate with stable command catalog, primary-source research, golden fixture variation, local-contained OpenSSH and Owner feedback converted into regression scenarios. Never hide residual risk.

### False confidence

Mandatory evidence labels and `REAL VPS: NOT TESTED`; Principal rejects overclaim.

### Owner lockout

Staged protocol, fresh disposable VPS, provider recovery/console, independent SSH session, active-port safety, firewall before/after checks and P0 handling.

### Diagnostic leakage

Central fail-closed redaction, seeded-secret tests, pseudonymized issue report, no unredacted export, public-repo warning.

### Insufficient failure evidence

Stable operation/error/command IDs, structured phase records, safe output, support bundle, exact artifact SHA.

### Cross-platform package cannot be executed

Separate built/package-inspected/startup-smoked/manual states; do not overclaim; create blocker/Principal decision for release claim.

### GitHub writes unavailable

Stop substantial untracked work and record auth blocker.

### Session interruption

Use Prompt 03; reconstruct from issues/branches/CI/ExecPlan.
